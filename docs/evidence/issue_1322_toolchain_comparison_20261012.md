# Issue 1322 same-runner toolchain comparison (2026-10-12)

Workflow runs: [38272857808](https://github.com/Yingqingxue/moonsmith/actions/runs/38272857808), commit `958745f`, and [38273799180](https://github.com/Yingqingxue/moonsmith/actions/runs/38273799180), commit `d107a9e`. Both Linux and Windows jobs succeeded in both runs. Each job installed the two official MoonBit toolchain bundles sequentially on the same hosted runner, verified each requested MoonC version against `moon version --all`, cleaned `_build` between them, and ran `scripts/test_issue_1322.ps1` against the same checked-in fixture and generated probe. The downloaded run artifacts contain per-version JSON reports (including exact MoonC versions) and a comparison summary.

The result repeated on a second independent workflow run: on both Windows runner instances, the native-debug result changed with the installed MoonBit toolchain while the recorded MSVC version remained the same. Linux reproduced the signature under both toolchains in both runs. The `native-release` and Wasm-GC controls passed in all eight per-platform/toolchain executions. MoonSmith's reference oracle classified the debug compile failure when present; the exact expected output is external to MoonSmith and comes from the upstream report.

This is repeatable evidence of a toolchain-bundle-associated change across two hosted runner instances per OS, not a confirmed root cause. The installer changes `moon`, `moonc`, and the bundled core together; the experiment does not isolate which component changed behavior, pin the hosted runner image, or control every dependency. Two comparisons per platform still do not establish whether the upstream behavior violates the language contract. Issue [moonbitlang/moonbit-docs#1322](https://github.com/moonbitlang/moonbit-docs/issues/1322) predates this project probe; this is not a MoonSmith discovery.
