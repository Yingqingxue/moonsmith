# Failure preserving reduction

The current reducer works on a program generated by MoonSmith's typed AST. Its
input is a seed and expression depth. A MoonBit command regenerates the AST,
applies accepted candidate indices, and emits the next candidate sources.
The PowerShell host runs each source on the selected backends and asks the
MoonBit oracle to classify the results.

The reducer first reproduces the baseline finding twice. It accepts a
candidate only when its complexity strictly decreases and its finding plus
reduction key match the baseline. The final source receives one more replay
before the result is saved.

Complexity is represented as a 64-bit score even though integer literals in
the generated language are 32-bit. This avoids overflow when ranking the
absolute value of `Int`'s minimum literal and when summing the costs of a
compound expression; host-side report validation also reads the score as a
64-bit integer.

For an output mismatch, the reduction key records which backends have equal
output. It permits literal output values to change while preserving the same
backend partition. For compile, runtime, timeout, and mixed failures, the key
records the failing backend, status, exit code, and normalized diagnostic.
Outputs from successful backends may change. Source file paths are masked as
`<case>`, per-case build artifacts as `<case-build>`/`<case-dir>`, and the
workspace root as `<workspace>`. Diagnostic text remains an exact match;
changing line numbers or message wording can still prevent reduction. A future
version may use a carefully verified diagnostic fingerprint for those cases.

When a reference output is available, the output mismatch key also records
which backends match that reference. A `reference-mismatch` key records that
the successful backends agree with each other while disagreeing with the
candidate program's freshly evaluated reference value. Each shrink candidate
gets its own expected output; the reducer never reuses the original program's
literal value.

Each run stores original and minimal source, attempt counts, accepted steps,
and both signatures. A unique run directory prevents one reduction attempt
from overwriting another.

The injected output mismatch is a harness test. It is never presented as a
MoonBit defect. The `-InjectOnlyWhenSourceContains` option makes this test
source dependent, so the reducer must reject candidates that remove the
triggering syntax.

CI additionally injects a mismatch only when seed 0's source contains
`_ms_valtype_run`, then reduces it with JS, Wasm, Wasm-GC, and native when the
runner has a C compiler. Run `37968510482` accepted 5 steps in 10 attempts,
lowering AST complexity from 39,300 to 18,133 while preserving `#valtype`, the
first `Double` field, the raising function, and `try?`. The uploaded reduction
record confirms the four-target matrix. The attempt budget was reached, so
this is proof of source-trigger preservation and replayable progress, not a
claim of a local minimum or of a compiler bug.

The same probe-specific injected reduction now includes both `native` and
`native-release` when a C toolchain is available. CI run
[37992067092](https://github.com/Yingqingxue/moonsmith/actions/runs/37992067092)
passed on Linux and Windows. The Linux artifact records the five-configuration
matrix, 5 accepted steps in 10 attempts, and complexity 39,300 → 18,133; the
attempt budget was reached. Windows also passed the reducer integration. Its
artifact contains both injected reduction records and their original/minimized
source files; the `native-release` target is present in the five-configuration
matrix. This verifies the upload path as well as configuration, without making
the injected mismatch evidence of a real compiler bug.

The #1322 regression now has a separate conditional path for exercising the
AST reducer on the generated probe's real, externally reported native-debug
compile-failure signature. It runs only on Linux when the generated probe
actually reproduces that signature; Windows/MSVC is a control and is not
forced into an injected failure. The check requires a smaller AST and source,
at least one accepted step, and the same reducer finding, while the reducer
itself independently checks the baseline and final replay against the same
failure key. The report and original/minimized corpus sources are included in
the CI artifact. The first Linux execution in [run 39102569713](https://github.com/Yingqingxue/moonsmith/actions/runs/39102569713)
produced a reducer record: seed 4/depth 3, 859 → 536 source bytes, complexity
10,110 → 1,001, three accepted steps in four attempts. The final record kept
the same native-debug compile-failure reduction key; JS, Wasm, Wasm-GC, and
native-release remained successful. The workflow was marked failed after this
record was produced because the wrapper incorrectly required exit code 0,
although `reduce_case.ps1` intentionally returns 1 for a retained finding.
That wrapper now accepts only exit 0/1, then requires valid JSON and actual
smaller source/AST output. A passing rerun of the corrected wrapper is still
pending. On this Windows workstation there is no C compiler, so this real
failure branch cannot run locally. #1322 remains an upstream report, not a
MoonSmith discovery.

A separate workstation run used a 100-attempt budget on the same deterministic
seed and target matrix. It accepted 15 steps in 84 candidate attempts, reduced
the source from 2,376 to 1,367 bytes and AST complexity from 39,300 to 11,014,
and exhausted the current one-step candidate set without exhausting its budget.
The final three-backend replay retained the same reduction key and all trigger
fragments. This is only a local minimum relative to the current AST candidate
set, not a globally minimal program. The JSON and minimized source are in the
ignored local run directory `.moonsmith/reduced/injected/0c412107c3170279/`
on the development workstation; CI uploads the test-run versions as an
artifact for 30 days.

## AST-node and cost metrics (2026-10-20)

The reducer manifest now reports an unweighted expression-node count in
addition to its weighted complexity score and source byte count. It also
records verifier invocations, target runs/executions, backend command time,
generation/reference/trace time, candidate-generation time, summed verifier
wall time, and total reduction wall time. Node count deliberately excludes
literal magnitude and loop bounds; it is an additional structural measure, not
the reducer's candidate-ordering score.

The deterministic injected-output-mismatch regression (seed 0, depth 2,
JS/Wasm/Wasm-GC; mismatch injected only when the source contains `(if`) was
rerun on MoonBit `0.1.20260920`. It reduced from 11 to 6 expression nodes
(45.5%), 148 to 113 UTF-8 source bytes (23.6%), and weighted complexity 4,045
to 2,004. It accepted 3 candidates in 8 attempts without hitting its attempt
budget; the final output is replay-checked. The run performed 11 verifier
calls (two baseline checks, 8 candidate attempts, and one final check), 33
target runs, and 18 backend execution attempts. On this workstation the
baseline-through-final-replay reduction phase took 45,292 ms; artifact hashing
and persistence are outside that stopwatch. Summed backend command time was
27,695 ms and summed verifier wall time 42,705 ms. These are single-run local
timings, not a benchmark. Component durations are separately rounded and
should not be added to claim an exact decomposition.

The injected finding is synthetic: the harness appends a marker to Wasm-GC
stdout. The final `finding` and `reductionKey` are preserved, including the
same backend agreement partition, but the full signature's literal stdout
changes from `-13` to `0` as the candidate source changes. This demonstrates
failure-class-preserving structural reduction on MoonSmith's generated AST;
it is neither a real compiler defect nor evidence about MoonReduce's
layout-only reducer. The raw report and exact sources are archived under
[`reducer_semantic_metrics_20261020`](evidence/reducer_semantic_metrics_20261020/).
The regression now requires both AST-node and byte counts to decrease and
checks that the verifier-call count equals candidate attempts plus the two
baseline and one final verification.

Current limits:

- Only MoonSmith generated programs can be reduced; arbitrary `.mbt` parsing
  has not been implemented.
- Candidate evaluation is sequential and bounded by `-MaxAttempts`.
- The output mismatch key preserves backend relationships but cannot prove
  that two different source programs trigger the same internal compiler bug.
- Native execution needs a local C compiler and is unavailable on the current
  workstation.
